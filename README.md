# סורק גראהם — S&P 1500

## חיבור Claude Desktop דרך MCP

אפשר לחבר את Claude Desktop לתיקייה באמצעות שרת MCP מקומי. השרת מספק קריאה,
כתיבה, חיפוש והרצת פקודות מתוך תיקיית הפרויקט בלבד. קובצי `.env`, קובצי סודות
ותוכן מפתחות חסומים אוטומטית.

התקנה:

```powershell
py -m pip install -r requirements.txt
```

הוסיפו ל־`claude_desktop_config.json` (בנתיב ההגדרות של Claude Desktop):

```json
{
  "mcpServers": {
    "graham-daily": {
      "command": "C:\\Python313\\python.exe",
      "args": [
        "C:\\Users\\yosefab\\OneDrive - Lapidot Group\\Documents\\Visual_Code\\graham-daily\\mcp_server.py"
      ]
    }
  }
}
```

החליפו את נתיב Python אם `py` מותקן במקום אחר. לאחר שמירת הקובץ, הפעילו מחדש
את Claude Desktop. אין להוסיף לקובץ ההגדרות את מפתחות Alpaca.

סריקה יומית אוטומטית של מדד ה-S&P Composite 1500 לפי הפילוסופיה של בנג'מין גראהם,
עם כלי המדידה של היום. עליה רצות שכבת איכות, שכבת תזמון טכני, וכלל המכירה של גראהם
כהתראה על הפוזיציות הפתוחות.

**הדפים החיים:**

## המסך המודרני

גראהם כתב את פרק 14 ב-1949, בעולם שבו ערך של חברה ישב במאזן: מפעלים, מלאי, ציוד.
היום הערך של חלק גדול מהחברות יושב בתוכנה, במחקר ובמותג, ומכפיל ההון מפספס אותו
לגמרי. שלושת המבחנים המאזניים של גראהם בחרו בשיטתיות בנקים וחברות נדל"ן — לא מפני
שהם עסקים טובים יותר, אלא מפני שיש להם מאזן גדול.

הפילוסופיה נשארה: **קודם בטיחות, אחר כך זול.** רק כלי המדידה הוחלפו.

| # | הקריטריון | הסף | מחליף את |
|---|---|---|---|
| 1 | גודל מספיק | מכירות מעל 1.5 מיליארד דולר | אותו קריטריון, מותאם לאינפלציה |
| 2 | יציבות רווחים | רווח חיובי בכל אחת מחמש השנים האחרונות | אותו קריטריון |
| 3 | איתנות פיננסית | חוב נטו עד פי 3 מהרווח התפעולי בתוספת פחת | היחס השוטף |
| 4 | החזר הון | דיבידנדים ורכישות עצמיות פחות הנפקות, מעל 2% | 20 שנות דיבידנד רצוף |
| 5 | מחיר זול | רווח תפעולי מעל 10% משווי הפעילות | מכפיל רווח ומכפיל הון |
| 6 | רווחיות | רווח גולמי מעל 20% מסך הנכסים | קריטריון חדש |

הציון הוא מתוך שש לכולם, בלי פטורים. חברה שאי אפשר לחשב עבורה מדד אינה מקבלת
פטור אלא נכשלת, ומסומנת בדף כ"לא ניתנת למדידה". זה הפוך מהגרסה הקודמת, שבה
פטור לבנקים העניק להם יתרון.

**מקורות:** קריטריון 4 מבוסס על כך שרכישות עצמיות החליפו את הדיבידנד כדרך
העיקרית שבה חברות אמריקאיות מחזירות מזומן. קריטריון 5 מבוסס על Gray & Carlisle,
*Quantitative Value* (2012), שמצאו ש-EBIT חלקי שווי פעילות הוא מדד הזול החזק
ביותר. קריטריון 6 מבוסס על Novy-Marx (2013).

## מאיפה מגיעים הנתונים

מרשות ניירות ערך האמריקאית, ישירות. ל-SEC יש API חינמי לנתוני XBRL, כלומר
המספרים כפי שהחברה הגישה אותם, בתגיות תקניות. זה מדויק בהרבה מספק נתונים חינמי,
ובעיקר — לכל נתון יש שדה `filed`, תאריך ההגשה בפועל.

| מסלול | מתי | למה |
|---|---|---|
| `sec_frames.py` | הסריקה היומית | מושך מושג חשבונאי אחד לכל היקום בבקשה אחת |
| `sec_facts.py` | הבדיקה לאחור | חברה אחת בכל פעם, עם תאריכי הגשה |

כשה-SEC לא זמינה או חסר בה שדה, הסורק נופל חזרה ל-Yahoo Finance. עמודת
`data_source` אומרת לכל מניה מאיפה הגיעו הנתונים.

### ניקוי הנתונים

ה-XBRL מדויק, אבל לא אחיד. כמה דברים שהקוד עושה כדי שהמספר יהיה המספר הנכון:

* **תגית לכל תקופה.** חברות החליפו תגיות לאורך השנים, למשל תגית ההכנסות עם
  כניסת ASC 606 ב-2018. בכל תקופה נבחרת התגית המועדפת מבין אלה שכבר הוגשו,
  ולא תגית אחת לכל ההיסטוריה. כך הכנסות שלפני 2018 לא נמחקות.
* **חוב בלי כפילות.** חוב ארוך טווח, החלויות השוטפות שלו והלוואות קצרות
  (`ShortTermBorrowings`, `CommercialPaper`) נסכמים. כשהחברה מדווחת את הסך
  הכולל (`LongTermDebt`) הוא מחליף את הפיצול ולא מתווסף אליו.
* **דיבידנד.** `PaymentsOfDividendsCommonStock`, `PaymentsOfOrdinaryDividends`
  ו-`PaymentsOfDividends`. חלוקות לחברות קשורות אינן דיבידנד לבעלי המניות.
* **תגית מיושנת.** שדה שהתקופה האחרונה שלו ישנה ביותר מ-400 יום מהמאזן האחרון
  מדלג, במקום להיכנס לחישוב עם מספר של לפני שלוש שנים.
* **חברה שהחליפה CIK.** כשחברת החזקות חדשה מחליפה את הישנה (XOM), הדוחות של
  שתיהן מאוחדים. הרשימה ב-`PREDECESSOR_CIKS` שב-`sec_facts.py`.

### מחירים

ברירת המחדל היא Yahoo Finance. כשמוגדר מפתח Alpaca, המחירים מגיעים משם:
נרות יומיים מתואמים לפיצולים ולדיבידנדים, עד מאה סימולים בבקשה, עם עימוד
מסודר. yfinance הוא מגרד של אתר ולא ממשק, והוא נוטה להחזיר עמודות חסרות
בהורדות גדולות — מה שהופך אותו למקור הכשל העיקרי בבדיקה לאחור.

בחשבון החינמי של Alpaca הנתונים ההיסטוריים מתחילים בסביבות 2016, ולכן בדיקה
לאחור שמתחילה לפני כן תקבל שורות חסרות בשנים הראשונות. יותר מזה: היקום
"נמדד" גדל בשנים הראשונות רק מפני שעוד מניות קיבלו מחירים, ולא מפני שהשוק
השתנה. הבדיקה מזהה קפיצה כזאת (פי 1.5 ומעלה בין תקופות) ומתריעה עליה. הבדיקה
האחרונה רצה על מחירי Yahoo, ובה היקום עמד על כ-1,300 מניות כבר מההתחלה.

### סודות להגדיר במאגר

Settings → Secrets and variables → Actions → New repository secret:

| שם הסוד | לְמה | חובה |
|---|---|---|
| `SEC_USER_AGENT` | ה-SEC דורשת כתובת יצירת קשר בכותרת. בפורמט `graham-daily your@email.com` | מומלץ מאוד |
| `ALPACA_API_KEY_ID` | מחירים מ-Alpaca | לא |
| `ALPACA_API_SECRET_KEY` | מחירים מ-Alpaca | לא |

בלי `SEC_USER_AGENT` הבקשות ל-SEC עלולות להיחסם. בלי מפתחות Alpaca הכל עובד,
פשוט על Yahoo. שום מפתח אינו נשמר בקוד או בקובץ — הקוד קורא אותם ממשתני סביבה
בלבד.

## הבדיקה לאחור

`backtest.py` — השאלה היחידה שבאמת חשובה: האם המסך הזה הוסיף משהו.

הטעות שהורגת כל בדיקה ביתית היא להשתמש במספר שלא היה ידוע אז. דוח של 2023
מתפרסם בפברואר 2024; מי שמחשב קריטריון ל-1 בינואר 2024 על אותו דוח "קנה" עם
מידע מהעתיד. כאן זה לא קורה: נלקח רק מה שהוגש עד תאריך האיזון, ודוח שהוגש
מחדש עם מספרים מתוקנים אינו דורס את הגרסה שהמשקיע ראה בזמנו.

**מה עדיין מוטה, ואי אפשר לתקן:** היקום הוא חברי המדד של **היום**. מי שפשט
את הרגל, נמחק או נרכש אינו שם. זו הטיית שרידות, והיא מטה את התוצאה כלפי מעלה.
כל מספר שיוצא משם הוא תקרה, לא הערכה. בנוסף: התשואה היא שינוי מחיר מתואם בלבד,
אין מס, ועלות המסחר היא אומדן גס.

הבדיקה רצה ידנית מלשונית **Actions**, ולא בכל יום — התוצאה משתנה רק כשמשנים
את המסך.

### התוצאה האחרונה

ספטמבר 2026, S&P 1500, איזון רבעוני, עד 30 מניות, יוני 2017 עד דצמבר 2025
(34 רבעונים). הקובץ המלא: `backtest_results.json`.

| | שנתי |
|---|---|
| התיק | +19.3% |
| היקום, משקל שווה | +16.3% |
| עודף | +3.0% |
| רבעונים שבהם התיק היכה את היקום | 18 מתוך 34 |
| מניות בתיק בממוצע | 26.6 |

סטטיסטיקת t של העודף הרבעוני היא כ-1.1, כלומר לא מובהקת. בתוספת הטיית השרידות,
המסקנה הזהירה היא "לא גרוע מהשוק", לא "מנצח את השוק". הבדיקה נמדדה **בלי
סטופ**, לפי כלל המכירה של גראהם בלבד.

## שלב האיכות

מבוסס על הצנרת של Gray ו-Carlisle: קודם פוסלים, ורק אחר כך מדרגים.

**פסילה**

* **מדד בניש** (1999) — סימנים של מניפולציה בדוחות. מעל 1.78- חשד ממשי.
* **מדד אלטמן** (1968) — סכנת חדלות פירעון. מתחת ל-1.81 מצוקה.
* **צבירות** (Sloan 1996, בגרסת התזרים של Hribar & Collins 2002) — הפער בין
  הרווח החשבונאי לתזרים התפעולי, חלקי סך הנכסים. מעל 10% נפסל. זו בדיקה
  שמשלימה את בניש בדיוק במקום שבו הוא חלש: לא מניפולציה, אלא חשבונאות
  אגרסיבית שהיא לגמרי חוקית.

**מגבלה שחשוב להכיר:** שלושת המודלים בנויים על מבנה דוחות של חברה תפעולית.
לבנקים ולחברות ביטוח אין מרווח גולמי ואין נכסים שוטפים מול התחייבויות שוטפות,
ולכן הפסילות מסומנות אצלן כלא רלוונטיות.

**דירוג** — ממוצע דירוגים אחוזוניים של ארבעה מדדים: EBIT חלקי שווי פעילות,
רווחיות גולמית, מומנטום של 12 חודשים בהשמטת החודש האחרון, ותשואת החזר הון נטו.

הדירוג נעשה **בתוך הענף** ולא על פני כל הרשימה. תשואת רווח תפעולי של בנק ושל
חברת תוכנה לא מדברות באותה שפה; כשמדרגים את כולם יחד, הרשימה מתמלאת בענף אחד
שבמקרה זול כרגע, והמשקיע חושב שבחר מניות כשבעצם בחר ענף. ענף שיש בו פחות מחמש
מניות מאוגד ל"כלל השוק".

## השכבה הטכנית

מבוססת על Constance M. Brown, *Technical Analysis for the Trading Professional*
(McGraw-Hill, 1999), ומצומצמת בכוונה למה ששייך לאופק של שנתיים:

* **כללי הטווח של ה-RSI** (פרק 1) — התעלה שבה ה-RSI נע תלויה במגמה. בשוק שורי
  תמיכה של 40 עד 50 והתנגדות של 80 עד 90, בשוק דובי תמיכה של 20 עד 30 והתנגדות
  של 55 עד 65. מחליף את 30/70 הקבועים. ירידה מתחת ל-38 נחשבת שבירת התעלה.
* **מומנטום של 12 חודשים** בהשמטת החודש האחרון.
* **מיקום מול ממוצע נע של 200 יום.**

מדד הקומפוזיט מפרק 12 אינו מחושב, מפני שהמחברת בחרה לא לפרסם את הנוסחה בספר.

**שני חסמים על איתות כניסה:** מניה שמחזור המסחר היומי שלה מתחת ל-2 מיליון דולר,
ומניה שהדוח שלה מתפרסם בתוך חמישה ימים. שניהם מורידים כניסה להמתנה ולא פוסלים
את המניה.

## כלל המכירה

גראהם פרסם ב-1976, בראיון ל-Medical Economics, כלל יציאה מפורש: למכור כשהרווח
מגיע ל-50%, ואם לא הגיע — עד סוף השנה הקלנדרית השנייה שאחרי הקנייה, מה שקורה
קודם. הוא טען שהכלל הזה, על סל מגוון, נתן כ-15% בשנה לאורך כחמישים שנות בדיקה.

הכלל נראה שרירותי, וזה בדיוק העניין. הוא לא מנסה לתזמן את השוק; הוא מונע משתי
הטעויות שהכי עולות כסף — להתאהב במניה שעלתה, ולהחזיק לנצח במניה שלא זזה.

לשימוש: לערוך את `positions.csv`, שורה לכל קנייה.

```csv
ticker,entry_date,entry_price,shares,note
KO,2026-03-14,58.20,100,
```

הריצה היומית מוסיפה את המחיר הנוכחי ומציגה את המסקנה בראש הדף הטכני. שום דבר
לא נמכר אוטומטית — זו התראה, וההחלטה שלך.

## שליחת פקודות לאלפקה

שני כלים מקומיים, מול חשבון הנייר כברירת מחדל. המפתחות נקראים מקובץ `.env`
בתיקייה או ממשתני סביבה, ולא יוצאים מהמחשב. הדף הציבורי ב-GitHub Pages לא
שולח פקודות.

```bash
python order.py buy LULU --entry 182.40 --qty 10              # יעד בלבד
python order.py buy LULU --entry 182.40 --qty 10 --with-stop  # יעד וסטופ
python order.py positions
python order.py check          # כלל המכירה ומצב פקודות היציאה
python order.py renew LULU     # חידוש פקודת יציאה שפגה או עומדת לפוג

python app.py                  # אותו דבר בממשק, ב-http://127.0.0.1:5000
python app.py --tailscale      # גם מהטלפון, דרך Tailscale בלבד ועם טוקן
```

כל אזור במסך (פוזיציות, פקודות, מועמדות) הוא חלון שנפתח ונסגר בלחיצה על הכותרת,
והמצב נשמר בדפדפן. כפתור **גרף** ליד כל פוזיציה פותח חלון עם מהלך המחיר מיום
הקנייה, קווי הכניסה, היעד והסטופ, ומתחתיו השיא, השפל ומה נשאר עד היעד ועד מועד
היציאה. תאריך הקנייה נלקח מ-`positions.csv`, ואם אין שם שורה, מהביצוע בפועל אצל
אלפקה. טבלת הפקודות מציגה 30 יום אחורה, כולל פקודות שבוצעו, שבוטלו ושפקעו, ולכל
קנייה כמה אחוזים יש מנקודת הכניסה עד הסטופ.

**קנייה לפי סכום.** בחלונית הקנייה אפשר לבחור כמות מניות או סכום בדולרים. אלפקה
מקבלת שבר מניה רק בפקודת יום, בלי GTC ובלי יעד מצורף, ולכן סכום מתפצל: המניות
השלמות נשלחות בפקודה הרגילה עם יעד +50%, והשבר שנשאר נקנה בפקודת יום נפרדת בלי
יעד. אם לא התבצע עד סוף היום, הוא מבוטל. חידוש פקודת יציאה מוכר רק מניות שלמות.

עם `--tailscale` השרת מקבל רק את המחשב עצמו וכתובות Tailscale, ומ-Tailscale רק
עם טוקן. הטוקן נוצר בהפעלה הראשונה ונשמר ב-`.env` בשם `APP_TOKEN`, והשרת מדפיס
כתובת שמכילה אותו: פותחים אותה פעם אחת בטלפון.

כל פקודה מוצגת במלואה ונשלחת רק אחרי הקלדת מילת אישור (BUY או RENEW). חשבון
אמיתי דורש `--live` ואישור נוסף.

**בלי סטופ כברירת מחדל.** הקנייה נשלחת כפקודת OTO: כניסה ויעד של ‎+50%. זה
כלל היציאה של גראהם, וזה מה שהבדיקה לאחור מדדה. סטופ לפי ATR נוסף רק עם
`--with-stop` (או תיבת הסימון בממשק), ואז הפקודה היא bracket.

**פקודת היציאה פוקעת.** אלפקה מבטלת פקודות GTC אחרי 90 יום, ואחזקה אצל גראהם
נמשכת עד שנתיים. `check` מראה לכל פוזיציה אם יש לה פקודת יציאה ומתי היא
פוקעת, ומתריע 14 יום לפני. `renew` מבטל את פקודות המכירה הפתוחות של הסימול
ושולח חדשה: limit, או OCO כשיש סטופ. את מועד היציאה לפי זמן אלפקה לא יודעת
לאכוף, ולכן `check` בודק אותו מול `positions.csv`.

### למה שני cron לשלב הטכני

GitHub מריץ cron לפי UTC בלבד, ושעון ישראל זז בין UTC+2 ל-UTC+3. לכן מוגדרות
שתי שעות, 05:00 ו-06:00 UTC. GitHub גם מתחיל ריצות מתוזמנות באיחור, לפעמים של
כמה שעות, ולכן הצעד הראשון לא בודק אם השעה בישראל היא בדיוק 08:00, אלא אם היא
08:00 או אחרי והשלב עוד לא נשמר היום. כך רצה ריצה אחת בכל בוקר, גם כשהיא מאחרת.

## הרצה מקומית

```bash
pip install -r requirements.txt
export SEC_USER_AGENT="graham-daily your@email.com"
# לא חובה:
export ALPACA_API_KEY_ID="..."
export ALPACA_API_SECRET_KEY="..."

# השלב הערכי
python graham_screener.py --universe sp1500 --out results.csv
python build_page.py --in results.csv --out docs/index.html --mode defensive
python build_page.py --in results.csv --out docs/enterprising.html --mode enterprising

# איכות, תזמון וכלל המכירה
python quality_screener.py --in results.csv --out quality_results.csv
python tech_screener.py --in quality_results.csv --out tech_results.csv
python positions.py --in positions.csv --out positions_status.csv
python build_tech_page.py --in tech_results.csv --positions positions_status.csv \
  --out docs/technical.html

# בדיקה לאחור
python backtest.py --universe sp500 --start 2015 --end 2025
```

לבדיקה מהירה על מניות בודדות:

```bash
python graham_screener.py --tickers KO,JNJ,PG,XOM,IBM
python graham_screener.py --tickers KO,JNJ --no-sec   # בלי שכבת ה-SEC
```
